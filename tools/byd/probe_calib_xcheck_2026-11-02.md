## 关键判别：偏离的物理来源（残差-距离回归）

以引擎常数（c0=−15）解码相对视觉的残差，按距离带：

| d 带 | n | 残差中位 | 该带偏好 c0 |
|---|---|---|---|
| [5,15) | 77,716 | −0.117 | +22.3（近距量化粗，噪声大） |
| [15,25) | 50,931 | −0.055 | +5.8 |
| [25,40) | 27,225 | −0.172 | +11.0 |
| [40,60) | 25,966 | −0.265 | +10.7 |
| [60,90) | 20,478 | −0.338 | +9.5 |

线性拟合 `res15 ≈ +0.00594·d − 0.0999`：**∝d 项主导**（0.34° 安装角当量，c0 当量 11.9 counts ≈ 实测 13），常数项 −0.10m 为反射点/视觉偏置量级（小）。

**解释链**：
1. c0=−15 的出身是 engine round-trip identity（radar_y_engine_labels.py:35，误差 ≤1.1mm）——它钉的是**引擎有效常数**，即「用 −15 能精确复刻厂商引擎的 y 输出」，这一点本轮再次成立；
2. 同一批帧的视觉配对偏好 c0≈−2..−3，且偏离严格 ∝d——引擎 y 与视觉 y 之间恒差 0.006·d 的安装型偏移；
3. 两者同时为真 ⟹ **厂商引擎默认值编码的是名义安装，实车安装偏差由其学习层吸收**——`_GeometryLearning` 之所以存在，就是为了这 13 个 counts；
4. c2f 仿射拟合（A≈0）当年未见此现象：其自由截距 B 恰好吸收了 K·Δc0 项。

## 对定案与移植的含义

- **y-wire 定案加强**：公式结构（engine round-trip）+ 默认常数（本轮复验）双重成立；解码器现行 `Y_CODE_ZERO=1024/c0=−15` 输出与厂商引擎逐位一致（显示级正确性不变）
- **厂商方法论立论被独立验证**：其 c0 plausible 域（|c0|≤128）、交叉校验（<8）、双窗（<2）、holdout 门（0.15/0.4）在我们的数据上全部按设计工作
- **本车视觉真值常数**：c0≈−2..−3（段间稳定）；显示级无需采用（维持引擎一致），控制级/视觉真值场景下这是逐车学习应收敛到的值
- **默认值贴敏感域下沿（3 counts）**：任何把默认 c0 当免检常数的下游使用都要过敏感曲线

## 方法论迁移建议（结合身份字段核查）

1. **立即可迁**（纯纪律，无依赖）：符号偏置验收（0.15/0.4）、具名 reason 计数、双窗稳定、plausible 域、段级 holdout—— multitarget 遗留监督（任务 3.5 门限定标）直接套用
2. **立即可迁**（配对军规）：等完整扫描再配、先配对后判歧义（裕度 0.5）、8 对连续 warmup——配对口径坑的疫苗
3. **有前置**（关联机制）：身份字段核查结论 = **仅代理键**——现行 trackId 是 slot 代数+距离门控派生（radar_multitarget.py:37, TRACK_ID_BASE=201），线上原生 track ID（vendor flags&32 语义）未解出。vendor 用 native 键曾把「同扫描帧重复身份」误阻塞率从 24-32% 修到可用；我们跨行移动目标的换绑风险同源。迁移判重/warmup 前需先在 F1–F3/D 块未钉死位里定位原生 ID 字段（独立小探针）
4. **暂缓**：d_off 学习（需 v_x 入档）、moving 门（需 carState 上下文入档）——均属 C-full 范畴，本轮判别分析表明对 c0 结论无增量
